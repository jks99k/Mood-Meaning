# 03. 프론트엔드 구현 지침

## 1. 기술 제한
HTML5, CSS3, Vanilla JavaScript만 사용한다. React/Vue/Next.js/TypeScript/Tailwind를 추가하지 않는다. 정적 페이지는 Vercel에서 제공하고 API 요청만 서버 함수로 보낸다.

## 2. HTML 구성
`index.html`에는 다음 영역을 의미 있는 요소로 구성한다.
- `header` 내비게이션
- `main`
  - 히어로 소개
  - 분석 폼 (`form`)
  - 결과 영역 (`section`)
  - 서비스/AI 안내
- `footer`

분석 폼 필수 요소:
- 연결된 `label`이 있는 `textarea`
- 글자 수 표시
- 분석 제출 버튼
- 입력 관련 오류 문구 영역

결과 영역 필수 요소:
- 감정 라벨
- 신뢰도 숫자 및 진행 바
- 분석 이유
- DB 저장 성공/실패 상태
- 참고용 결과 안내

## 3. JavaScript 동작
`js/app.js`는 다음 순서로 동작한다.
1. DOM 요소를 가져온다.
2. 입력 이벤트에서 앞뒤 공백을 기준으로 글자 수를 계산한다. 입력 중에는 실제 입력 길이도 명확히 안내한다.
3. 제출 이벤트를 가로채고 기본 페이지 이동을 막는다.
4. 입력값을 trim하고 비어 있는지, 2,000자를 넘는지 검사한다.
5. 검증 실패 시 입력창 근처에 오류를 표시하고 서버를 호출하지 않는다.
6. 요청 시작 시 버튼을 비활성화하고 로딩 문구를 표시한다.
7. `fetch('/api/analyze', { method: 'POST', headers: {'Content-Type':'application/json'}, body: JSON.stringify({ text }) })` 호출.
8. 응답의 HTTP 상태와 JSON 형식을 확인한다.
9. 성공 시 결과 UI를 갱신한다.
10. 실패 시 사용자용 오류를 표시한다.
11. `finally`에서 버튼을 복구한다.

## 4. API 응답 렌더링
- `sentiment` 값은 허용된 세 값만 UI 라벨로 매핑한다.
- `confidence`는 숫자 범위를 확인한 뒤 표시한다.
- `reason`과 오류 문구는 `textContent`로 넣는다. `innerHTML`에 사용자 입력/AI 응답을 연결하지 않는다.
- 진행 바의 `aria-valuenow` 및 시각적 너비를 confidence 값에 맞춘다.
- 저장 상태는 `saved: true/false`를 기준으로 구분한다.
- 알 수 없는 값은 성공 화면으로 표시하지 않는다.

## 5. 상태 관리
외부 상태관리 라이브러리는 사용하지 않는다. 일반 변수 또는 DOM 상태로 충분하다.
- `idle`
- `loading`
- `success`
- `error`

한 번 요청 중일 때 중복 제출은 불가능해야 한다. 이전 결과가 있을 때 새 요청이 시작되면 이전 결과를 지우거나 “새 분석 중”으로 명확히 표시한다. 이전 결과와 새 결과를 혼동하게 두지 않는다.

## 6. 보안과 개인정보
- 브라우저 JavaScript에는 OpenAI 키나 Supabase service role 키가 없어야 한다.
- 사용자가 입력한 텍스트는 HTML로 해석하지 않는다.
- 콘솔에 입력 원문이나 전체 API 응답을 출력하지 않는다.
- 페이지에 AI 분석과 DB 저장 사실을 알리는 문구를 둔다.

## 7. 프론트엔드 검증
- 빈 문자열 제출 시 서버 요청이 발생하지 않는지 확인
- 2,000자 입력 허용, 2,001자 입력 차단 확인
- 로딩 중 버튼 비활성화 확인
- 성공 응답에서 감정/신뢰도/이유가 표시되는지 확인
- API 오류에서 재시도 가능한 메시지가 표시되는지 확인
- 저장 실패 응답에서도 분석 결과가 유지되는지 확인
- 키보드만으로 입력/제출 가능 여부 확인
- 360px 화면에서 가로 스크롤이 없는지 확인
