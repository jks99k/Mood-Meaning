# 02. UI/UX 디자인 지침

## 1. 디자인 방향
첨부된 피자 브랜드 웹사이트의 시각 언어를 참고하되, 음식점 콘텐츠를 복제하지 않고 감성 분석 서비스에 맞게 재해석한다. 키워드는 **따뜻한 에디토리얼, 대담한 타이포그래피, 강한 컬러 블록, 정돈된 카드**다.

## 2. 컬러 토큰
아래 값은 구현을 위한 시작값이다. 전체 화면에서 일관되게 사용하고 임의의 새 브랜드 컬러를 계속 추가하지 않는다.
- `--ink`: `#062A35` (딥 틸/네이비, 기본 배경)
- `--teal`: `#06465A` (보조 딥 틸)
- `--rust`: `#B7441D` (번트 오렌지, 강조 섹션)
- `--mustard`: `#F2C230` (버튼/강조)
- `--cream`: `#FFF4D8` (카드/밝은 배경)
- `--paper`: `#F8F5EA` (기본 밝은 면)
- `--text-dark`: `#14272A`
- `--text-light`: `#FFF9ED`
- 감정 상태는 별도 색상 토큰으로 구분하되, 색상만으로 뜻을 전달하지 않는다. 긍정은 녹색 계열, 부정은 붉은 계열, 중립은 청회색 계열을 절제해 사용한다.

## 3. 타이포그래피
- 메인 제목: 시스템에 설치된 세리프 계열(예: Georgia, `serif`).
- 본문/버튼/입력: 시스템 산세리프(예: Arial, `sans-serif`).
- 큰 제목은 굵고 대비가 강하게, 본문은 읽기 쉬운 크기와 줄 간격으로 구성한다.
- 외부 폰트 사용은 필수가 아니다. 외부 폰트를 추가한다면 로딩 실패 시 시스템 폰트로 자연스럽게 대체한다.

## 4. 페이지 구성
### A. 상단 내비게이션
- 좌측: 텍스트 로고 `Mood & Meaning`
- 우측: `서비스 소개`, `분석 방법` 등 페이지 내부 앵커 링크
- 우측 끝에 작은 강조 버튼 `문장 분석하기`
- 모바일에서는 간결하게 줄바꿈/간격 조정한다. 별도 햄버거 메뉴는 필요하지 않다.

### B. 히어로 영역
- 딥 틸 배경, 큰 세리프 제목 예시: “Words have a feeling.”
- 한국어 보조 문구: “한 문장에 담긴 감정을 가볍게 들여다보세요.”
- 한쪽에 작은 라벨/설명 요소를 두어 매거진 표지 같은 인상을 준다.
- 첫 화면에서 입력 영역으로 자연스럽게 시선이 이동해야 한다.

### C. 분석 입력 패널
- 번트 오렌지 또는 밝은 크림 패널을 사용해 히어로와 대비한다.
- 큰 라운드 컨테이너 안에 텍스트 입력창, 글자 수(0/2000), 분석 버튼을 배치한다.
- 입력 placeholder 예시: “오늘 경험한 일이나 누군가에게 전하고 싶은 문장을 적어보세요.”
- 입력창 아래에 “입력한 문장은 AI 분석을 위해 외부 서비스로 전송되고 분석 결과 저장을 위해 DB에 저장될 수 있습니다. 민감한 개인정보는 입력하지 마세요.” 안내를 읽기 쉬운 크기로 표시한다.
- 버튼은 머스터드 배경과 어두운 텍스트를 기본으로 한다.

### D. 분석 결과 영역
- 입력 패널 아래에 결과 카드가 나타난다. 분석 전에는 숨기거나 안내용 빈 상태로 보여준다.
- 결과 상단: `ANALYSIS RESULT` 작은 캡션
- 중앙: 큰 감정 라벨 `긍정`, `부정`, `중립`
- 신뢰도: 숫자와 `%`, 진행 바를 함께 표시
- 분석 이유: 크림색 인용/설명 카드
- 하단: 저장 상태 및 참고용 결과 안내
- 감정마다 라벨, 아이콘/기호, 색을 함께 사용한다. 예: `+ 긍정`, `− 부정`, `○ 중립`.

### E. 하단 안내/푸터
- 체크 패턴 가로 구분선을 사용해 참고 이미지의 특징을 반영한다.
- 서비스 목적과 AI 결과의 한계를 간단히 설명한다.
- 불필요한 메뉴, 리뷰, 가짜 고객 후기, 존재하지 않는 브랜드 정보는 만들지 않는다.

## 5. 패턴과 장식
- 체크 패턴은 CSS 반복 선형 그라디언트로 만든다. 이미지 파일을 새로 찾거나 생성할 필요가 없다.
- 얇은 테두리, 겹친 패널, 둥근 모서리를 제한적으로 활용한다.
- 장식은 콘텐츠의 가독성을 방해하지 않아야 한다.
- 참고 이미지의 피자 사진, 음식 메뉴, 고객 리뷰, 가격표, 주문 버튼을 그대로 사용하지 않는다.

## 6. 반응형 기준
- 모바일 우선으로 구성하고 360px, 768px, 1024px, 1440px 폭에서 확인한다.
- 모바일: 한 열, 제목 크기 축소, 입력창 전체 폭, 버튼 전체 폭 권장.
- 태블릿/데스크톱: 콘텐츠 최대 폭을 제한하고 좌우 여백을 확보한다.
- 어떤 폭에서도 가로 스크롤이 생기지 않아야 한다.

## 7. 상태별 디자인
- 기본: 입력창과 안내 표시
- 로딩: 버튼 비활성화, 버튼 문구 변경, 진행 표시
- 성공: 결과 카드 표시 및 결과 영역으로 자연스럽게 안내
- 입력 오류: 입력창 근처에 구체적인 안내
- 서버 오류: 결과 대신 재시도 가능한 오류 카드
- 저장 오류: 분석 결과는 유지하고 저장 실패 문구를 별도 표시

## 8. 접근성/완료 기준
- 모든 입력에는 연결된 `label`이 있어야 한다.
- 버튼은 실제 `<button>` 요소로 만든다.
- 키보드 포커스가 눈에 띄어야 한다.
- 상태 변화는 `aria-live` 영역으로 알린다.
- 본문 대비와 버튼 대비를 확인한다.
- 감정은 색상 외에 텍스트로도 표시한다.
- 모바일 360px에서 주요 요소가 겹치거나 잘리지 않아야 한다.
